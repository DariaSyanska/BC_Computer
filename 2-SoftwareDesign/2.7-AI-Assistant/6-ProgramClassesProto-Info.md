# Рекомендації щодо створення UML-діаграми прототипу програмних класів (ЛР №5)

Діаграма прототипу програмних класів має бути технічно деталізованою та відповідати наступним вимогам:

1. **Структура класів**:
   - Кожен клас повинен мати чітко визначену назву (іменник в однині).
   - Обов'язкова наявність секції атрибутів (полів) та операцій (методів).
   - Для кожного атрибута має бути вказаний тип даних (String, Integer, Date тощо).

2. **Модифікатори доступу**:
   - Використовувати стандартні позначення: `-` (private) для полів та `+` (public) для методів.

3. **Логіка операцій**:
   - Методи класів повинні безпосередньо реалізовувати функціональні вимоги (FR), описані в проєкті.
   - Назви методів мають починатися з дієслова (наприклад, `saveDiaryEntry()`, `getHeartRate()`).

4. **Зв'язки між класами**:
   - Відобразити типи зв'язків: асоціація (простий зв'язок), агрегація (частина-ціле), композиція (суворе володіння) або успадкування.
   - Вказати множинність зв'язків (1..1, 0..*, 1..*), де це необхідно для логіки бази даних.

5. **Відповідність**:
   - Програмні класи мають базуватися на сутностях з `UML-ConceptClasses.puml`, але бути адаптованими до програмної реалізації.
